# Refusals — the generic patterns, what replaces them, and what must survive

The admin console was generated by an AI from a product brief. The brief was
good and the palette it chose was the signed brand; the generic quality lives
in how that palette was used. §1 names the patterns so the diagnosis step can
point at them by name. §2 names the wider clichés we do not import from
elsewhere. §3 is as important as the first two: what the console already does
right, which a redesign must carry forward.

## 1 · In this console today — pattern → replacement

| the generic pattern | where it shows | what replaces it |
|---|---|---|
| 10 px radius on everything | every card, input, button, chip | 6 px on surfaces and controls, 999 px on pills — the approved system's values |
| a card for every section, cards inside cards | drawers, editors, item card | section titles on a shared surface; a card only where it separates concerns |
| generic icon as the logo | sidebar (`leaf`) | the dandelion mark and the serif wordmark, once |
| accent colour as decoration | icons, headings, chips, links at once | one accent per screen: the primary act and the selected state |
| cold greys | `--a-ink-4` captions, hints | a warm muted (`#908b7d` family) for secondary text |
| drop shadow for hierarchy | cards, panels | tone: `--a-sunk` against `--a-surface`, hairline borders |
| the dashboard KPI tile | counts in big type for things nobody decides on | a number earns display size only where a decision hangs on it |
| rounded-pill button everywhere | all actions look equally important | one primary per view; secondary as quiet outline; destructive as text until confirmed |
| table rows at 48 px with padded cells | ADataTable defaults | 36–40 px rows; padding between groups, not inside every cell |
| placeholder empty states | "אין נתונים" with a grey icon | the brand's thin line illustration, one plain sentence, one action |
| labels and hints in the same grey weight | forms | label: ink, 600; hint: muted, 400; required state in copy, not an asterisk |
| decorative page intro paragraphs | several views | a one-line page subtitle that states the count or the rule, or nothing |
| motion on load | transitions on first paint | none; motion only on a state change |

## 2 · Not imported from the wider AI aesthetic

These are the looks that read as "generated" in 2026. None of them belongs to
a pharmacy's back office, and none is used as a shortcut:

- Warm cream with a serif display and a terracotta accent.
- Near-black with one acid-green or vermilion pop.
- Purple-to-blue gradients, glassmorphism, glow.
- Inter or Space Grotesk as the "safe" default — Hebrew UI is Assistant here.
- Emoji as section markers; icons as bullets.
- Everything centred; hero sections in an admin.
- `rounded-lg` everywhere; an accent rail on every card.
- Numbered markers (01 / 02 / 03) on content that is not a sequence.
- Illustrated "humans with laptops" placeholders.
- Dark mode as a feature — the console is light by decision; the reviewer's
  OS theme must not leak into form controls (`color-scheme: light` stays).
- Scroll-jacking, cursor effects, parallax — never.
- Procedural / generative graphics as decoration. (Hand-written SVG for a
  chart that shows data is not decoration; the ladder chart is the model.)

## 3 · Already right — survives every redesign

- **The chip system** for status: amber waiting, blue in progress, teal/green
  done, red problem, gray neutral, purple special — with its tone + background
  pairs. Refine the chip; never replace the system.
- **URL is the state.** Every open record, filter, page and sort is an address;
  editors and dialogs are actions. A redesign never moves state out of the URL.
- **One table component** (`ADataTable`) with its own horizontal scroll bar
  above the header. Restyle it once; never fork it per screen.
- **The chip strip** (`ChipStrip`) that shows one row of fifty chips and says
  how many are behind it.
- **Every field has its own label.** No header-row-over-bare-inputs editors.
- **Approval gates** (`ActionGate`) in front of single risky actions, logged.
- **Confirmation dialogs that say what will happen** (`effects`), with reason
  capture where it matters.
- **Toasts that report the outcome** of both the local change and the write.
- **LTR islands** for codes, numbers, tracking numbers, SKUs inside RTL text.
- **The "R" badge** marking what is live in the pharmacy's real system — a
  review aid, never shown against a real API.
- **Reproducing the pharmacy's own reports exactly** (the stock-analysis
  export) rather than redesigning them — some screens are not ours to design.
